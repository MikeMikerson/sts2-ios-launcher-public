# Third-party components

The game itself is not included, and the build reads no game file. The app holds none of the game: it downloads the game from Steam after the player signs in. Game code, assets, trademarks, and bundled components retain their respective ownership and terms.

This repository's own code is under the MIT license in `LICENSE`. The parts below keep their own licenses.

## Source included here

The Steam service code retains its upstream MIT notice in `src/STS2Mobile.Steam/LICENSE`, including its copyright attribution. That notice must remain with copies of the code.

## What the built app holds

The app runs on the Mono runtime from .NET 10. The build compiles the .NET code ahead of time and embeds it, with the runtime, in one framework. The app's own files are the engine executable (`FullGame`), three frameworks, a small main pack of the host's files (`FullGame.pck`), a placeholder icon and the usual iOS metadata. It holds no separate `.dll` files.

Each person builds the app themselves; no prebuilt app is published. The components below are compiled or linked into that build. The notice files are in the downloaded inputs, at the paths given (all ignored by git).

In the main pack (`FullGame.pck`), the launcher's typefaces, each under the SIL Open Font License 1.1, with its license text beside it in the pack and in `src/STS2Mobile.FullGame/fonts/` (tracked, from Google Fonts' repository):

- Grenze (The Grenze Project Authors, Omnibus-Type).
- Atkinson Hyperlegible Next and Atkinson Hyperlegible Mono (their Project Authors, for the Braille Institute of America).

In `Frameworks/STS2Mobile.FullGame.framework` (the .NET code, the Mono runtime and the texture encoder):

- Mono runtime (`libmonosgen-2.0.a` and its static components), version 10.0.12, from the `Microsoft.NETCore.App.Runtime.Mono.ios-arm64` runtime pack: MIT (.NET Foundation and Contributors). The build checks the library against the hash pinned in `tools/dependencies.json` and patches it.
- .NET base class libraries, AOT compiled, from the same pack: MIT.
- .NET native libraries from the same pack (`libSystem.Native`, `libSystem.Globalization.Native`, `libSystem.IO.Compression.Native`, `libSystem.Net.Security.Native`, `libSystem.Security.Cryptography.Native.Apple`) and Brotli (`libbrotlicommon`, `libbrotlidec`, `libbrotlienc`): MIT. The pack's third-party notices cover the code these include, such as zlib-ng and Brotli.
  - Notices: `tools/ios-dotnet/packs/Microsoft.NETCore.App.Runtime.Mono.ios-arm64/10.0.12/LICENSE.TXT` and `THIRD-PARTY-NOTICES.TXT` beside it.
- GodotSharp 4.5.1 (NuGet): MIT (Godot Engine contributors). The build rewrites the package's `GodotSharp.dll` before compiling it (`tools/mono/build_mono.py`).
- SteamKit2 3.4.0 (NuGet): LGPL-2.1-only (Ryan Stecker and the SteamRE team). The package's full license text is `license.txt`.
- protobuf-net and protobuf-net.Core 3.4.29 (NuGet, SteamKit2 dependencies): Apache-2.0.
- ZstdSharp.Port 0.8.7 (NuGet, SteamKit2 dependency): MIT.
- System.IO.Hashing 10.0.1 (NuGet, SteamKit2 dependency): MIT, with its own `THIRD-PARTY-NOTICES.TXT`.
- QRCoder 1.6.0 (NuGet): MIT.
- Mono.Cecil 0.11.6 (NuGet, includes `Mono.Cecil.Rocks`): MIT (Jb Evain). The app uses it on the phone to verify and patch the game's assembly.
  - Notices for the NuGet packages: each package's `.nuspec` license field, under `analysis/full-game-mono/packages/<id>/<version>/` (a copy of `.tools/nuget/packages`).
- astc-encoder (Apache License 2.0, Arm Limited) and bcdec (MIT, or public domain under the Unlicense, as its header says): the texture encoder, built from the pinned sources.
  - Notices: `vendor/texture-encoder/sources/astc-encoder-<commit>/LICENSE.txt`, and the end of `vendor/texture-encoder/sources/bcdec/bcdec.h`.
- Startup code generated by the .NET LibraryBuilder pack 10.0.12: MIT. Notices: `tools/ios-dotnet/packs/Microsoft.NET.Runtime.LibraryBuilder.Sdk/10.0.12/THIRD-PARTY-NOTICES.TXT`.
- QuickMatch, when setup has it (embedded and woven into the game on the phone): MIT, Copyright (c) Michael Farrelly; its source is the sts2-quickmatch repository. It includes Concentus, a C# port of the Opus codec, under its own BSD-style license (`licenses/Concentus-LICENSE.txt` in QuickMatch's release).

In the engine executable (`FullGame`):

- Godot Engine 4.5.1 iOS export template (`libgodot.a`): MIT, plus the licenses of the third-party code the engine includes. The template archive has no separate notice file. The engine carries its copyright and license text inside itself, and the full list is `COPYRIGHT.txt` in Godot's source at tag `4.5.1-stable`.
- MoltenVK, from the same template: Apache License 2.0 (The Khronos Group). The template has no separate notice file for it.
  - Input: `.tools/godot/editor_data/export_templates/4.5.1.stable.mono/ios.zip`.

In `Frameworks/libGodotFmod.ios.template_release.universal.framework`:

- FMOD Godot integration (fmod-gdextension 6.1.0-4.5.0): MIT (Utopia-Rise and Alex Fonseka). Notice: `vendor/fmod/2.03.06/GODOT_FMOD_LICENSE.txt`.
- FMOD Engine 2.03.06 runtime libraries (`libfmod_iphoneos.a`, `libfmodstudio_iphoneos.a`), from the same release archive: FMOD's own license from Firelight Technologies, separate from the integration's MIT license. The archive does not include FMOD's license text.

In `Frameworks/libspine_godot.ios.template_release.framework`:

- Spine runtime for Godot (spine-godot 4.2, built for Godot 4.5.1): the Spine Runtimes License from Esoteric Software. The archive does not include the license text; `vendor/spine/4.2-godot4.5.1/manifest.json` records its address.

Preparation metadata embedded in STS2Mobile.GamePatcher: Lib.Harmony.Ref 2.4.2 (MIT, Andreas Pardeike), and Microsoft.NETCore.App.Ref 9.0.20 (MIT, Microsoft and contributors). These reference assemblies let Cecil read mod attributes on the phone; they are data and are never loaded as executable assemblies. Harmony's reference package license is embedded as `metadata/Harmony.LICENSE`; package notices are under `.tools/nuget/packages/lib.harmony.ref/2.4.2/LICENSE` and `.tools/nuget/packages/microsoft.netcore.app.ref/9.0.20/`. Runtime Harmony remains unavailable: the app weaves supported patches at preparation and replaces the calls.
